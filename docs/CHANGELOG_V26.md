# v26 변경사항

## 데이터베이스 분리

- 전자문서·계정·조직은 기존 `DB` 유지
- 회계 전 기능은 `ACCOUNTING_DB` 사용
- R2 첨부파일 바인딩은 `FILES` 유지
- 환경 타입에 `ACCOUNTING_DB` 추가

## 전자결재·회계 안전 연계

- 기존 DB에 `accounting_outbox` 추가
- 결의서 생성·승인·반려 이벤트를 문서 상태 변경과 같은 D1 배치로 저장
- 회계 DB 장애가 문서 승인 자체를 되돌리지 않도록 분리
- 이벤트 고유키와 원천문서 고유키로 중복 전표 방지
- 실패 원인, 시도 횟수, 다음 재시도 시각 기록
- 관리자용 연계현황 및 재처리 기능 추가

## 성능 개선

- `accounting_monthly_summary` 월별 집계표 추가
- 대시보드·예산집행·시산표·결산·특화통계는 원시 분개 전체 재집계 대신 월별 집계 사용
- 결의서·전표·원장·후원자·기부금·자산·카드내역 조회 건수 제한
- 카드 날짜검색을 `substr()` 방식에서 범위검색으로 변경
- 자주 쓰는 연도·날짜·상태 조건에 인덱스 추가
- 특화회계 첫 화면의 초기 목록을 최근 20건으로 제한

## 스키마 관리 개선

- API 요청 중 `CREATE TABLE`, `CREATE INDEX`, 기준정보 삽입을 실행하지 않음
- 실행 중에는 필수 테이블과 버전만 빠르게 검증
- DDL은 `migrations/main`, `migrations/accounting`으로 분리
- 회계 스키마 버전 `2026-07-26.4`

## 회계 처리 개선

- 수동전표·역분개·기부금·법인카드 전표가 월별 집계에 즉시 반영
- 결의서 최종 승인 시 분개와 월별 집계가 같은 회계 DB 배치로 확정
- 반려 시 결의서 상태만 반려 처리하고 전표는 생성하지 않음
- 기안자와 결재자가 같은 즉시승인도 동일한 연계절차 적용

## 운영 점검

- `/api/health`에서 두 D1, 회계 스키마 버전, 연계현황 확인
- 회계관리 관리자 화면에 연계 성공·대기·처리중·실패 수 표시
